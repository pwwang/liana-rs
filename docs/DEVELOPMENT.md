# Development

## Toolchain

Rust **stable**, edition 2024 (requires ≥ 1.85; developed against 1.93.1).
`rustfmt` and `clippy` are required — CI runs both.

> (1.93.1) on `PATH`, and 1.79 cannot build edition 2024. Put rustup first:
> ```bash

> cargo --version   # must print 1.93.x, not 1.79.0
> ```

## The three gates

CI (`.github/workflows/ci.yml`) runs exactly these on push and PR:

```bash
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

Run them before every commit:

```bash
cargo fmt --all && cargo clippy --all-targets -- -D warnings && cargo test
```

Formatting is configured in `rustfmt.toml` (`edition = "2024"`, `max_width = 100`).
Clippy warnings are errors — do not `#[allow]` one away without a comment saying why.

## Layout

```
crates/liana-core   library: scoring methods (cellphonedb, geometric_mean, rank_aggregate, …)
crates/liana-cli    `liana-rs` binary
testdata/fixtures/  vendored inputs + golden outputs from scverse/liana (see FIXTURES.md)
testdata/expected/  oracle-generated reference outputs + per-file .meta.json
scripts/oracle.sh   regenerates testdata/expected/ from the pinned Python oracle
bench/              paper-recipe dataset generator and benchmark runner
ops/logs/           run logs (gitignored)
```

Dependency versions live in `[workspace.dependencies]` in the root `Cargo.toml`;
crates pull them with `dep.workspace = true`. Heavy deps (anndata, polars,
nalgebra-sparse) are deliberately *not* wired in yet.

## The parity oracle

`testdata/expected/` is generated by the **pinned** Python oracle — liana 2.0.0
(`V2.0.0`, commit `c59472ccc9de8360dbbf5016db75f8abde08dd3e`). That pin is
enforced at runtime: `scripts/oracle.sh` refuses to run if the installed liana's
version *or* its `direct_url.json` commit differs.

```bash
scripts/oracle.sh                       # regenerate everything (~10 s)
LIANA_ORACLE_PYTHON=/path/to/python scripts/oracle.sh
```

It reads the input fixtures listed in its `FIXTURES` table, writes
`testdata/expected/<fixture>__<method>__p<N>.csv` plus a matching `.meta.json`
(versions, seed, `n_perms`, fixture + resource sha256, row/col counts).

**Determinism is a hard requirement.** The run is single-threaded (`n_jobs=1`)
and seeded (1337); rerunning must produce byte-identical CSVs and identical
metas apart from `generated_at`. Verify after touching the script:

```bash
cp -r testdata/expected /tmp/exp1 && scripts/oracle.sh
diff -r --brief /tmp/exp1 testdata/expected | grep -v meta.json   # must print nothing
```

The oracle venv is `/home/pwwang/p0a/venv/bin/python` (liana 2.0.0, numpy 2.5.3,
numba 0.68.0). Fixture classification (input vs golden output, and why the three
`*.csv` fixtures are golden outputs whose inputs are *not* vendored) is documented
in `testdata/FIXTURES.md` — read it before adding a fixture.
